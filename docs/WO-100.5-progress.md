## Phases in the build, and every toggle's default

All five phases are in `0.23.1`.

| toggle | default | command / flag |
|---|---|---|
| Ghost `NoAI` spawning | **off** | `mp_ghost_noai_on` / `mp_ghost_noai_off` |
| Ghost `NPC_NAI` class swap | **off** | `mp_ghost_nai_on` / `mp_ghost_nai_off` |

is file-triggered and one-shot, and does nothing until
`kcdmp-combatwrite.txt` names a command.

## WO-101 candidates

1. **The block action on an NPC.** Every shipped call site fires
   `CombatModule 0x76500` on an AI-driven body; it was only tried on the
   player, where `C_Player` has already been caught overriding combat
   behaviour. Needs a maintainer and an injected DLL, not two players.
   **Top of the list.**
2. **Probe the Mannequin tag writer.** One `type()` call answers whether
   `AI.SetAnimationTag` / `Action.PersistantEntityTag` are registered on this
   build. If they are, the receiver can drive tags directly instead of choosing
   from a fixed clip set.
3. **A native edge hook for the action channel**, replacing the 250 ms poll
   that can merge a fast press-commit-release into one edge.
4. **Directional locomotion clips.** `dir` crosses the wire already and there
   is nothing to select with it.
5. **The byte-wide relay player id still wraps** (WO-75, still unfixed).
6. **`Test-WO99Synthetic.ps1` always exits 2** — its scenario prints its own
   `RESULT:` line and never sets `OUT`, so the harness reports failure even on
   39/39. Pre-existing; anything reading its exit code is misled.
