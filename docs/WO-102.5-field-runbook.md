# WO-102.5 — field-session runbook

**For the two-machine session.** Both machines on the WO-102.5 build (matched
set: agent, pak, `KCDMP.dll`, relay). Everything WO-102.5 changed is
**(synthetic)** or **(code-verified)** until this runs — no game ran this
session, at all. Nothing below has been seen live.

Console commands are **argless** (the console drops arguments) except the two
marked `#Lua` — those take a real argument and MUST be typed with the leading
`#`, which evaluates the line as Lua directly rather than as a console
command.

| toggle / command | on | off | shipped default | what it does |
|---|---|---|---|---|
| host NPC authority | `mp_authority_host_on` | `mp_authority_host_off` | **on** | unchanged from WO-102 |
| pause lever | `mp_authority_pause_on` | `mp_authority_pause_off` | **on** (WO-102.5 Phase 1) | solo-tested only, findings §1.1 |
| native NPC scan | `mp_npc_scan_native_on` | `mp_npc_scan_native_off` | **off** | run `mp_npc_scan_compare` first — §2 below |
| culling | `mp_npc_cull_on` | `mp_npc_cull_off` | **on** | owned-but-far NPCs stop streaming |
| authority radius | `#KCD2MP_SetAuthorityRadius("<m>")` | — | 45 m | **not** a console command — see the note above |
| status | `mp_wo102_status` | | | every WO-102 flag + this client's role |
| known-answer check | `mp_npc_scan_compare` | | | diffs the native scan's last push against a fresh Lua enumerate |
| resync | `mp_resync_npcs` | | | one-shot NPC position/life-state push from the owner |
| probe | `mp_probe_npc_pause` | | | WO-102 §3.3, single machine |

Bundle at the end, **from both machines**: `agent.log`, `kcd.log`,
`kcdmp-native.log` / `kcdmp-native.mirror.log`, and the relay log from the
host. `mp_summary` (or `mp_wo102_status`) on both before quitting.

## 0. Before anything else — WO-102's own gate, unchanged

Read `docs/WO-102-field-runbook.md` §0 first if it has not run this build.
The pause-lever probe now matters more than it did: it ships **on** this
time (WO-102.5 Phase 1), and its solo-only caveat still holds — this is
the first time it will ever run under a real two-machine puppet stream.

**⚠ Never run `mp_probe_npc_pause` against an NPC actively engaged in
combat.** Found live this session (findings §6.1.1): the probe's own 2 m
`SetWorldPos` displace-and-restore, run on `ttkc_man_3` while it was
mid-fight, was immediately followed by the player being launched into the
air. Causation is not proven (the player's own position telemetry went
flat/stale for the whole window, so it neither confirms nor rules it out),
but the timing lines up almost exactly with the probe's own ~10 s
duration, and displacing an active combatant mid-melee is exactly the kind
of thing that could confuse hit detection or a grapple state. The probe's
validated, safe use case remains what WO-102 always specified: an ambient
NPC, not seated, not in dialogue, and now — not fighting anyone either.
This does not implicate the real pause lever (`mp_wo102_pause`), which
never displaces position — only the diagnostic probe does.

## 1. The native NPC scan known-answer check — before trusting it at all

1. Solo or with a peer, stand near a handful of NPCs. `mp_npc_scan_native_on`.
2. Wait ~5 s for a scan to land (`MP-NPCSCAN dir=native …` in `agent.log`,
   `NPCSCAN: first scan OK …` in `kcdmp-native.mirror.log`).
3. `mp_npc_scan_compare`. Read `MP-NPCSCAN dir=compare … only_lua=… only_native=…`
   in `kcd.log`.
   * `only_lua` **must be empty**, or every name in it explained. Each one
     means the native scan missed an NPC the Lua walk finds — the scan is
     not trustworthy until this is empty.
   * `only_native` names are **expected** — native does not replicate Lua's
     mod-entity/mounted-horse/name-pattern exclusion by design (findings
     §2.2). Not a failure by itself.
4. If `only_lua` is empty across a few compares in different spots, the
   toggle has passed its known-answer gate. The cost comparison (native vs
   Lua `dur_ms`) still has no dedicated per-path cadence line this session
   (findings §2.3 item 5, a named gap) — eyeball `MP-NPCSCAN dir=native …
   dur_ms=` against how long the game feels like it hitches, if at all.

## 2. The radius runbook — solo, one session

**The shipped radius is whichever is the largest that holds, not 150 by
assumption.** Run this before ever setting the radius above 45 m for real
play.

For each of **45 m (default) / 90 m / 150 m**, at each of a **village** and
a **dense town**, with the native scan **on** and **off**:

1. `#KCD2MP_SetAuthorityRadius("<m>")`. Confirm in `kcd.log`:
   `WO1025-RADIUS set=<m> was=<prev>`.
2. Stand roughly centred in the area. Wait 10 s for a rescan.
3. Record, from `kcd.log`/`agent.log` over the next 30 s:
   * NPCs owned — count `KCD2MP.npcTracked` entries (`mp_wo102_status` does
     not print this directly; count `NPC-SYNC tracking` lines minus
     `untracking` lines since the last `WO102-AUTHORITY scan anchors=`
     line, or add a temporary `#for n in pairs(KCD2MP.npcTracked) do
     System.LogAlways(n) end; System.LogAlways("---")` count).
   * Scan duration: `MP-NPCSCAN dir=native … dur_ms=` (native on) — no
     equivalent exists for the Lua path this session (the named gap above).
   * Emit-tick spacing: the WO-100 §10 frame-time proxy — time between
     consecutive `NPC-SYNC` log lines during steady movement.
   * Packets per second: count `npc_state` lines emitted in a fixed window.
4. Toggle `mp_npc_scan_native_on`/`_off` and repeat step 3 at the SAME
   radius/location for the native-vs-Lua comparison.
5. **The decision**: the shipped radius is the largest of {45, 90, 150} where
   none of the above degrades noticeably (no visible hitch, packet rate
   stays sane, NPC count is not absurd for the area). A dense town at 150 m
   is where this is expected to fail first (≈70,000 m² vs 45 m's ≈6,400 m²,
   about eleven times the area) — if it does, that is the honest result,
   not a bug.

## 3. The fight — combat is the expensive category

1. Pick a fight (a bandit camp, a duel) inside whatever radius §2 settled
   on. `mp_npc_cull_on` (default).
2. Fight it. Watch for: NPCs beyond `cullRadius` (30 m default) not
   streaming (expected — `WO1025-CULL` lines are quiet by design, only
   re-entry logs), an engaged NPC's culling exemption holding (it should
   never stop streaming mid-fight — `NPC_ENGAGE_RANGE_SQ` keeps it inside
   `cullRadius` by construction, findings §3.1).
3. If the fight runs long enough to test a co-location exit (one player
   disengages and walks far away while the other keeps fighting): confirm
   `WO1025-COLOCATE event=exit … frozen=N` counts the fighting NPC as frozen,
   not released, and that it releases the instant the fight ends
   (`WO1025-COLOCATE deferred release now clear: <name>`).
4. Siege-scale (many NPCs at once) is the case the maintainer actually
   cares about — a radius that survives a market may not survive it. Not
   run this session; the first live attempt is this runbook's real test.

## 4. The falsifiable condition — two players, one NPC

The test the whole WO exists for. Both players attack the SAME NPC at the
same time.

**Pass**: the NPC does not phase into the ground, teleport, or run off.
`MP-AUTHORITY-VIOLATION` reads zero across the whole session.
`MP-NPCDIVERGE` never fires (host authority refuses the release and logs a
violation instead — WO-102 §4.3; a violation here under the pause lever ON
means the pause is not actually stopping the local brain, the "loud log"
WO-102's own design wanted).

**Fail modes to watch for specifically**, each pointing at a different
piece of this WO:

* A violation with `paused=1` in the line → the pause lever is on but not
  actually suppressing the brain (WO-102 §4.3's own diagnostic, still true).
* The NPC teleports at a co-location boundary crossing → the transition
  logic (Phase 4) is not actually preventing a stale resume; check
  `WO1025-COLOCATE` around the timestamp.
* The NPC is owned by one machine but visibly driven by both → `auth_owner_changes`
  in `MP-SUMMARY-MOD` should be **zero** under host authority; any non-zero
  value is the lead (WO-102 §7.3's own A/B headline, unchanged by this WO).

## 5. What this runbook cannot settle, stated plainly

Every number in Phase 3/4 (radius defaults, cull radius, the 60/90 m
hysteresis band, the 10 s dwell) is a first guess this session had no way to
measure against a live game. Running §§2–4 is how they get corrected, not
this document.
