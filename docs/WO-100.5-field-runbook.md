# WO-100.5 — field-session runbook

**For the session when the second player is available.** Written so it can be
followed without re-deriving anything. Build **0.23.1** on **both machines** —
see §7.

Everything below is either **(synthetic)** or **(observed solo)**. Nothing in
Phases 2, 3 or 4 has been seen with two machines.

---

## 0. Before you start

1. Both machines on **0.23.1**. New wire fields mean a mismatched pair silently
   loses them (§7).
2. Launch through the KCDMP launcher as usual (the solo-probe route in WO-100
   §10 — plain launch plus manual injection — is for native probes only; it
   gives you no agent and no relay).
3. `mp_summary` at the end of the session, on both machines, and keep both
   `kcd.log`s. Most of what this runbook asks for is read out of them
   afterwards, not watched live.

## 1. Every toggle this WO ships

All console commands are **argless** — the console drops arguments, so
`mp_x on` answers "Too many arguments" and a bare `mp_x` passes the literal
`%LINE`.

| toggle | default | command | what to watch when flipped |
|---|---|---|---|
| **Ghost class swap** | **off** | `mp_ghost_nai_on` / `mp_ghost_nai_off` | Almost certainly leave off. It cannot reach the primary spawn at all (the engine builds `NPC` whatever `ClassName` says) and where it does apply it costs hit registration entirely — §3. | **Ghost NoAI** | **off** | `mp_ghost_noai_on` / `mp_ghost_noai_off` | **The one that matters.** Applies to the NEXT spawn, so follow with `mp_remove_all` or a reconnect. Watch `MP-GHOSTCORR` and `MP-NPCFIGHT` — see §2. |

## 2. The `NoAI` tug-of-war measurement — the deferred half of Phase 0

Solo testing established what `NoAI=true` costs and keeps (§3). What it cannot
establish is the thing it exists for: whether WO-98's sub-metre tug-of-war
actually disappears when the body has no brain to contend with the position
stream.

**Procedure.**

1. Both players stand in a **dense-NPC scene** — a market, a tavern, a gate at
   a busy hour. Density matters: proximity authority and the yield rule are
   both proximity-gated.
2. `mp_ghost_noai_off`, `mp_remove_all`, let the ghost respawn. Move around
   each other for **three minutes**. Do not fight.
3. `mp_ghost_noai_on`, `mp_remove_all`, respawn. Repeat the same three minutes,
   in the same place, at the same pace.
4. Afterwards, from both `kcd.log`s, compare between the two runs:
   * `MP-GHOSTCORR … corr_mean_m= corr_max_m= snaps=` — the correction the
     smoother had to apply. **This is the number.** If the brain was fighting
     the stream, `corr_mean_m` falls in the `on` run.
   * `MP-NPCFIGHT` against `MP-NPCYIELD` — contention events and how often the
     arbiter had to act.

**What a null result means.** If `corr_mean_m` is unchanged, the ghost's brain
was never a significant writer and WO-98's tug-of-war has another cause. That
is a real finding, not a failed test — record it.

**The cost of `on`, so it is a decision and not a surprise:** the ghost stops
defending itself (WO-26's reactive combat is that brain). It stays perceptible,
stays a hit target and stays a crime victim — those were measured solo (§3).

## 3. The perception question, with two real machines

Solo testing answered this for a *probe body*. It has never been answered for a
*ghost*, and the asymmetry it would create is the thing worth seeing:

> guards on the local machine react to the local player normally; guards on the
> peer's machine see nobody where that player stands.

**Procedure.** One player stands in a restricted area (or commits a small
crime) in view of a guard. The other player watches **their own screen**, where
that player is a ghost body.

* With `mp_ghost_noai_off` (default), both machines should show a guard
  reacting.
* With `mp_ghost_noai_on`, the ghost keeps class `NPC`, so it should *still* be
  perceived — that is exactly what `NoAI` was chosen to preserve. **If it is
  not, that is a refutation of §1.4 of the findings and the toggle should go
  back to off permanently.**

Solo scoreboard for reference, from the engine's own
`Skirmish event: HitTarget` lines across one 71,829-line log:

| body | `HitTarget` registrations |
|---|---|
| `NPC_NAI` | **0** (across two trials and many hits) |
| `NPC` | 2 |
| `NPC` + `NoAI=true` | **7** |

## 4. The yield A/B still outstanding from WO-99

Never run. Thresholds ship as **0.30 m displacement / 10 consecutive ticks /
1.0 m re-pin**.

The 2026-09-16 cabin scene showed contention of **7 cm** — *below the 0.30 m
threshold by design*, so that scene would never have yielded and its absence of
`MP-NPCYIELD` lines proves nothing about the rule.

**First knob:** `#KCD2MP_SetNpcYield("0.10 10 1.0")` — drop the displacement
threshold to 10 cm, which is above the cabin scene's 7 cm but well under a real
brain walking away. Then watch `MP-NPCYIELD state=yield` and `state=repin`
counts against `MP-NPCFIGHT`.

## 5. Phase 4 validation carried from WO-100 — 111 synthetic tests, never seen live

None of this has run with two machines. All of it is read from the logs
afterwards.

* **Swing reason codes.** `MP-SWING hop=queued … reason=`. Before WO-100 every
  one of fourteen distinct failures reported as `ok=0`. Any `reason=` other than
  `0`/`ok` is now a specific, nameable failure — record which ones appear at
  all.
* **Inbox counters.** `MP-SUMMARY section=swinginbox` →
  `accepted / applied / refused / expired / waited / gaveup / dropped /
  peak_depth / bound`.
  * `waited > 0` with `gaveup = 0` means the 750 ms precondition deadline is
    doing its job. **750 ms is a guess, not a measurement** — the give-up line
    prints the real waited time, so tune it from that.
  * `dropped > 0` means the queue bound was hit; report the number.
* **The body-generation rule.** A swing that crossed a respawn must not play on
  whatever body took that ghost slot. Test it deliberately: one player swings,
  the other dies or reloads a save at the same moment. Expect
  `reason=expired`, not an animation.

## 6. First reads carried from WO-99.5

Grep these on both machines before anything else; they are cheap and they have
caught real defects.

| grep | why |
|---|---|
| `MP-DMG dir=drop` | a hit that was never sent. WO-99 found the local player being sampled instead of the target this way. |
| `MP-GHOSTPKT … stale=` | the peer's emitter suspended. Compare against your own heartbeat: 100% of the >2.3 s inbound ghost gaps on 2026-09-16 were sender suspension, zero were transport. |
| `MP-NPCYIELD` | §4. |
| `MP-SUMMARY` (periodic and final) | the whole session in structured lines. |
| swing `sid`/`rsid` pairing | a swing sent on one machine and received on the other should pair. An unpaired `sid` is a lost event; an unpaired `rsid` is one that arrived from nowhere. |

New in this build, worth a first look:

| grep | why |
|---|---|
| `MP-ANIM section=outbound` | `reads` / `refused` / `disabled`. `disabled=1` means the local DLL never answered the body-state query — the agent and DLL are not a matched set. |
| `MP-ANIM section=ghost` | per-peer `pace_changes` / `dir_changes` / `stance_changes`. Zero changes across a session where the peer was clearly running means the channel is dead, not quiet. |
| `MP-ANIM reject=unknown-ordinal` | the peer sent a body-state value this build cannot name. Should never appear on a matched pair. |
| `MP-ACTION section=inbound` | attack edges crossing the wire. Every one currently ends `dispatch=dropped-no-receiver` **by design** — Phase 1's block write was refused by the engine, so there is nothing to dispatch to yet. Seeing them arrive at all is the result. |
| `MP-ACTION section=inbound reject=` | `StaleOrDuplicate` / `Expired` / `UnknownKind` / `Malformed`. Any `Malformed` is a bug in this build, not a field condition. |
| `MP-GHOSTCORR` | §2. |

## 7. Matched-set warning

**Both machines must run 0.23.1.** This build adds wire fields:

* Position/Ghost flag `0x04` and five body-state bytes — a 0.22.x receiver sees
  an unrecognised packet length and **ignores the packet entirely**, so a
  mismatched pair loses position sync, not just animation.
* `0x3B`/`0x3C` — a 0.22.x relay does not forward them, so the action channel is
  simply absent.

And within one machine, the **agent, the pak and KCDMP.dll are a matched set**:

* an agent newer than the DLL gets no body state (logged once,
  `MP-ANIM … disabled=1`) and falls back cleanly;
* a pak older than the agent ignores the four extra `KCD2MP_UpdateGhost`
  parameters and runs the legacy inference.

Both degrade rather than break — but both mean you are not testing what you
think you are testing.

## 8. What this session cannot settle

Stated so it is not attempted and mistaken for a result:

* **The native block write.** It was refused by the engine on the player across
  six argument combinations (findings §2.3). The next step is to try it on an
  **NPC**, which is what every shipped call site does — that needs a maintainer
  at a keyboard with the DLL injected, not a two-player session.
* **Driving Mannequin tags directly onto a remote body.** The writer
  (`AI.SetAnimationTag` / `Action.PersistantEntityTag`) has never been probed
  for registration on this build. One `type()` call answers it.
